## Application standard

Use service-owned functions or existing static service methods with explicit typed inputs, actor context and an `AsyncSession`. Do not introduce a generic repository or inheritance framework. Endpoints bind transport and identity, delegate, and adapt typed results to their existing v1 format. Application services own authorization, public visibility, persistence orchestration and domain events. Models own relationships and constraints.

The shared route boundary owns the ordinary HTTP transaction through response validation. Session dependencies enlist in that boundary; services flush before consuming generated values and do not commit. Worker/standalone session contexts retain their own transaction ownership. Specialized independent transactions must be named and documented (for example durable authentication failure accounting). Failed operations, explicit HTTP error responses and cancellation roll back. Critical external work belongs in the same transaction's outbox; delivery is idempotent. Existing HTTP errors/envelopes remain adapters until each domain's contract is verified.

Declared streaming responses retain the existing dependency lifetime because Research's AI stream currently performs persistence inside its iterator. That is an explicit compatibility exception pending Research migration: errors after streaming headers cannot change the HTTP status. Ordinary responses close their sessions before sending; background work must open its own session.
